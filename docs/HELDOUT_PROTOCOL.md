approved stage 2 with the arms "box + scribble (scribble post-hoc)" after the [development study](DIRECT_DEV_20261104_RESULTS.md).

[`assets/heldout_v1/manifest.json`](../assets/heldout_v1/manifest.json) (SHA256 `50e59b14…e85b`). The code verifies every
scene file against the manifest before use, and both files are part of the run contracts.

## Question

On scenes never used for development or tuning, does direct instance conditioning (InstanceDiffusion, external)
produce more images with the right objects (count, colour/attribute, shape) than ControlNet and the best OCSD route,
and at what naturalness and cost? This is a comparison of existing methods on our benchmark protocol, not a new
architecture claim.

## Arms (seeds 0 and 1, same scenes)

| arm | method | role |
|---|---|---|
| `direct_box` | InstanceDiffusion official core, boxes + phrases, official MIS merge | primary (selected by the stage-1 rule) |
| `direct_scribble` | same + 20 ink points per instance | **post-hoc exploratory**, added after stage 1 |
| `controlnet` | SD 1.5 ControlNet scribble on the scene sketch, cn_scale 1.0 (paper_v2 tuned value) | baseline |
| `instance_repair_count_matte_soft` | OCSD route with count-aware repair and learned soft matte, foreground_screen settings | best reviewed OCSD route |

Direct arms: 50 PLMS steps, MIS 0.36, alpha 0.8, CFG 7.5, FP16 UNet autocast, FP32 VAE, 22 696 UNet sample calls in
total, child cap 3600 s. ControlNet/OCSD: the existing pipeline (`TIER="heldout_screen"`, 30 steps, object steps 20,
K = 2, R = 1, best-of 5 inside the OCSD route as before), generation cap 180 min per Run all, resumable. No tuning,
reranking across arms, extra seeds, reruns or image selection on these scenes.

## Endpoints and analysis (fixed now)

* **Primary endpoint:** per image, from the blind review, structure success = count, colour and shape all marked pass.
* **Primary tests (2):** `direct_box` vs `controlnet` and `direct_box` vs `instance_repair_count_matte_soft`. Unit =
  scene (18); per-scene success rate = mean over the two seeds; exact two-sided sign test over scenes where the arms
  differ; Holm correction over the two tests; rates with 95 % bootstrap CIs over scenes.
* **Secondary (descriptive, CIs only):** naturalness 0/1/2, most-natural picks, and OWLv2/CLIP metrics (count
  accuracy, OPR, count error, mIoU, relation accuracy, joint layout success, CLIP), paired bootstrap over scenes.
* **Exploratory:** every comparison involving `direct_scribble`; results by object-count bin.
* **Cost:** wall time, sampling calls (UNet/ControlNet/GLIGEN) and peak memory per arm, per architecture, never
  presented as equal FLOPs. Failed or missing images are reported, not replaced.
* Review: 36 sheets (sketch + A/B/C/D in a seeded random order per sheet), key stored separately; one reviewer.

## How it runs

`RUN_ALL.ipynb` with `RUN_MODE="heldout"`: cell 3d runs the 72 direct images in a child process; the experiment cells
then install the locked scenes (stage A), import the direct images with checksum checks, generate ControlNet and OCSD
(B), evaluate all 144 images with OWLv2/CLIP (C) and write the report, the review sheets and two ZIPs (D, G). Every
part resumes on the next Run all with `RUN_ID` empty.

## Limits

InstanceDiffusion is an external method (Wang et al., CVPR 2024). Inputs are instance-separated sketches with phrases
and boxes, not raw sketches. Methods differ in steps and architecture; the comparison is of methods as configured.
One reviewer; automatic detectors miss shape and naturalness errors (see earlier reviews).
