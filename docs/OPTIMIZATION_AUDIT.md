## Actual workflow

`RUN_ALL.ipynb` is generated by `tools/make_notebooks.py`. Data are constructed by `data.py`;
`stages.py` freezes pilot scenes for tuning, creates experiment jobs, tunes baselines and OCSD,
then delegates to `Runner`. M1 builds per-object masks/boxes/prompts. M2 samples K crops with
ControlNet, selects with Grounding DINO/SAM/CLIP; M3 learns token embeddings and LoRA per scene.
M4 either denoises the background separately then blends, or runs the joint OCSD-v2 trajectory.
M5 modifies cross-attention, applies energy updates and verifies/retries or repairs failed regions.
GLIGEN uses its pretrained grounding U-Net; Collage uses the same M2 objects plus SDEdit.
OWLv2 is the main evaluator, independently of the Grounding DINO verifier. `report.py` averages
seeds per scene, bootstraps scene means, and uses Wilcoxon with Holm families.

## Verified implementation defects and priorities

| Priority | Evidence in original implementation | Consequence / action |
|---|---|---|
| P0 | `Runner.run_items` skips any existing PNG; `_gen_signatures` records config only, and baseline signatures omit steps/CFG/negative prompt | Changed code/input/model can reuse old images. Isolate runs by provenance and validate artifact signatures/checksums. |
| P0 | `methods.m2_key` contains only K and phrase/class mode; `m3_key` omits learning rates and attention loss weight | Incompatible intermediates can be shared. Include actual dependency fields and input fingerprints. |
| P0 | `metrics.image_level_quality` hashes only basenames; `_ref_metrics` keys only paths | Replacing pixels at unchanged paths reuses old quality scores. Hash contents and evaluation settings. |
| P0 | FID selection filters to available files without enforcing requested pairs | Incomplete methods can silently have different sample counts. Require complete requested sets. |
| P0 | `_run_grid` checks images, but not completeness of evaluated rows before selecting a winner | Evaluator failures can change the tuning population. Fail selection on missing/duplicate rows. |
| P0 | notebook uses `git reset --hard`, tracks moving main, suppresses stage exceptions and automatically pushes results | Local edits can be lost, partial runs can look successful, and publication is implicit. Preserve local code, record exact SHA, propagate stage failures, make upload configurable; the user later requested restoring its enabled default. |
| P0 | `build_quickdraw_scenes` has one RNG for the whole build but skips existing scenes | Extending pilot to paper differs from a fresh build at the same seed. Seed each scene independently and store the new benchmark separately. |
| P1 | `Runner._run_scene` computes one foreground with cfg0 for an entire M2 group | A different placement configuration can reuse the wrong foreground. Compose per placement configuration. |
| P1 | M3 always trains against noise regardless of scheduler prediction type | Incorrect target for v-prediction backbones. Follow scheduler target type. |
| P1 | LoRA initialisation uses global RNG and retains first injected rank | Results can depend on method order; later rank changes are ignored. Seed local initialisation and rebuild changed ranks. |
| P1 | `paired_tests` emits p=1 for fewer than six finite pairs and no paired-effect CI | Unrun/insufficient evidence looks like a valid test. Report effective n/status and paired bootstrap CI. |

## Quality, cost and uncertainty

The historical E3 results and slides favour tuned GLIGEN and Collage over full OCSD on QuickDraw.
They do not prove that removing M3/M5 improves quality universally. The separate sampler gives
scene conditioning only the end of its trajectory at small alpha; joint sampling can lose anchors
or duplicate objects while improving background coherence. These are algorithmic hypotheses,
not conclusions from the CPU tests. Preserve all strong baselines and negative ablations.

For context, the historical `results/tables/E3_quickdraw.csv` reports these means (not new results):

| Method | OPR (%) | mIoU | KID × 1000 |
|---|---:|---:|---:|
| GLIGEN | 82.2 | 0.669 | 29.02 |
| Collage | 84.2 | 0.616 | 41.78 |
| OCSD | 74.0 | 0.541 | 74.32 |
| OCSD-v2 | 73.2 | 0.406 | 33.22 |

The source table contains uncertainty intervals; this compact excerpt is descriptive and does not
establish significance. OCSD-v2's lower KID alongside lower layout scores motivates checking the
control/appearance tradeoff, not selecting a winner using one metric.

M2 candidate sampling scales with object count and K; M3 adds per-scene optimisation. Best-of-N
and verification add variable work, so the name “compute-matched” alone is not evidence of equal
cost. Log actual U-Net calls/sample-equivalent work as well as wall time. Auxiliary models and
cached GLIGEN consume VRAM beyond the main engine. CPU timings do not predict Colab throughput.

The frozen tuning split excludes scene IDs from paper/full evaluation; M3 learns identity from each
scene's generated object crops, not from its COCO reference photograph. The synthetic constructor can
reuse raw QuickDraw drawings across distinct scenes. Raw-drawing overlap, actual failure categories
and pretrained detector bias still need auditing on the new real-data run; scene-ID disjointness alone
does not establish raw-sample independence. GPU peak memory and OOM recovery also remain unverified.
